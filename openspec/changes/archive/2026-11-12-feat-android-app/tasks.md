# Tasks

## 1. 工程骨架

- [x] 1.1 在 `Android/` 建立 Gradle 工程，模块 `:core`（纯 Kotlin JVM）和 `:app`（Compose，minSdk 26），`settings.gradle` 只包含这两个模块。验证：`./gradlew projects` 列出 `:core` 和 `:app`。
- [x] 1.2 `:app` 的 Manifest 危险权限只有 `CAMERA`，额外只声明震动所需的普通权限 `VIBRATE`，不声明 `INTERNET` 与存储权限；主 Activity 窗口设置 `FLAG_SECURE`，启用 edge-to-edge 与 Material 3 动态取色。验证：合并后的 manifest 无 `INTERNET`／`ACCESS_NETWORK_STATE`／存储权限，`FLAG_SECURE` 与动态取色在运行时确认。

## 2. Core 引擎

- [x] 2.1 在 `:core` 实现 Base32 解码（忽略空格和连字符，拒绝空串、非法字符和错误填充）以及 HOTP/TOTP，行为对准 `openspec/specs/totp-core/spec.md`，不另写算法规则。验证：JUnit 覆盖 RFC 4226 `755224`、`84755224`，RFC 6238 `94287082` 与 SHA-256 `68084774`，以及空密钥、负计数器、非 6/8 位、非正周期都抛错。
- [x] 2.2 在 `:core` 实现 `otpauth://totp/` 解析与序列化：默认 SHA-1、6 位、30 秒；拒绝非 totp、缺 secret、SHA384、非 6/8 位、周期小于 1。序列化结果能被同一解析器还原 secret、算法、位数和周期。验证：JUnit 覆盖完整 URI、默认值、拒绝用例，以及一行文本的往返。

## 3. 加密存储

- [x] 3.1 Room 把元数据与密文分成 `accounts`、`secrets` 两张表，元数据表不含密钥列。验证：`SchemaTest` 读导出的 schema 断言 `accounts` 无 `secret` 列、`secrets` 只有 `ciphertext`；查询按插入顺序。
- [x] 3.2 用 Android Keystore 的 AES-256 主密钥和 Tink `AES256_GCM` 按账户 id 存取密文；缺失密钥的元数据在组装时跳过；删除时同时清掉元数据与密文。验证：`AccountStoreTest` 仪器测试覆盖往返、密文不等于明文、缺密钥跳过、删除与重命名。

## 4. 添加入口

- [x] 4.1 相机页用 CameraX 和捆绑的 `com.google.mlkit:barcode-scanning` 识别二维码。恰好一个被 `core` 接受的 URI 时震动一次、入库并回到列表；否则留在扫码页且不入库。无相机权限时请求权限，拒绝后不打开相机。验证：用固定图像的仪器测试或假扫描器覆盖合法、非法和拒绝权限三条路径。
- [x] 4.2 扫码页和首页提供相册入口，使用 `ActivityResultContracts.PickVisualMedia`，不申请存储权限。一张图里一个合法 URI 则入库并回列表，否则 Snackbar 说明原因且不入库。验证：不声明读存储权限；假图片路径覆盖成功和失败。

## 5. 首页列表

- [x] 5.1 首页按仓库顺序显示卡片：首字母圆形徽章、站点与用户名各一行且中间省略、等宽大号验证码、剩余时间环。剩余不超过 5 秒时环和验证码以动画切到警示色。空仓库显示空状态和添加入口，不自动建账户。验证：两个账户的预览或 UI 测试顺序正确；5 秒与 6 秒两种颜色不同。
- [x] 5.2 点击卡片复制未分段的验证码。自动清空默认开启时，30 秒后仅当剪贴板仍是该验证码才清空。分段显示默认开启，6 位码显示为 `404 162`，复制仍是 `404162`。验证：单元测试格式化函数；清空逻辑用假时钟，覆盖“内容未变”和“内容已被替换”。
- [x] 5.3 长按提供重命名和删除。重命名按第一个空格拆成站点和用户名，空白名拒绝。删除先确认，确认后同时删密钥和元数据，取消则两处都不变。验证：仓储测试覆盖成功重命名、空白名、确认删除和取消删除。

## 6. 设置与备份

- [x] 6.1 设置页两个开关：复制后自动清空（默认开）、验证码分段显示（默认开），写入 DataStore，重启后保持。验证：默认值读自 DataStore 缺失时的回退，切换后的持久值需在设备上确认。
